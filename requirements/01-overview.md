# 01. 概要・目的

通勤中に「やりたいこと」をやれたかを、到着時の通知にワンタップで答えると、ペットのハムスターが育つ iPhone アプリ。

## 課題・狙い・方針

- **課題**: 通勤時間を有効活用したいのに、手軽な YouTube や SNS の流し見に負けてしまう。あとで「本を読みたかった」と後悔する。
- **狙い**: 記録そのものを目的にせず、「ハムスターが育つ」ことを続ける動機にする。サボると元気がなくなることも、続ける理由にする。
- **方針**: 移動の状態(歩き・自転車・電車・車)は自動で判定し、ユーザーが答えるのは「やれたかどうか」だけにする。この自動判定をアプリの特徴の一つにする。

## 1日の流れ(平日)

アプリが動くのは、乗車時のひと声と、到着時の「やれた?」の2つの瞬間。

| 時刻(例) | できごと | アプリの動き |
| --- | --- | --- |
| 7:50 | 家を出る | 通勤の開始を自動で検知 |
| 7:52 | 自転車 | ジオラマのハムスターも自転車に乗る |
| 8:02 | 電車に乗る | 通知でひと声(「Kindle、開こう!」) |
| 8:27 | 会社に着く | 通知で「やれた?」(✅ / ❌) |
| 19:10 | 帰りの電車 | 朝と同じくひと声 |
| 19:41 | 自宅に着く | 通知で「やれた?」(遅くなっても送る) |

## ペルソナ

### 主ペルソナ(依頼者本人)

- 自転車10分 + 電車20分で通勤する。電車は半分くらい座れる。
- 普段は YouTube を流し見して、本(Kindle は別端末)を読みたかったと後悔する。手軽さに負けてしまう。
- 通知は無視しがちで、最初だけやりそう。
- 記録が溜まるだけでは続かないが、ペットが育つなら嬉しい。
- iPhone を使う。

### 検証用ペルソナ(仕様の弱点を探すために想定した5人)

| ペルソナ | 状況 | 現仕様で崩れる点 | 対応 |
| --- | --- | --- | --- |
| 車通勤 | 片道40分、運転中はスマホを使えない | 運転中に通知が出る | 運転中は通知しない。駐車後に通知。やりたいことに音声学習なども登録できる |
| 満員・長距離 | 片道90分、乗り換え3回、ほぼ立ち | 毎日サボり扱いで弱る | 「休んだ」の選択肢を将来検討 |
| 週2出社 | 出社日が不定 | 通勤日が少なく育たない | 曜日ごとの ON/OFF と、臨時のお休みを設定できる |
| 勉強したい人(Android) | 資格試験、片道30分 | 自動で取れるのに毎回タップする | Android の自動判定を将来検討 |
| シフト勤務 | 夜勤あり、出退勤がバラバラ | 帰宅通知が深夜・早朝に来る | 場所検知で通知し、通知の時間帯設定を将来検討 |
